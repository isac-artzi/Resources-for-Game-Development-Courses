Advanced Game Testing and Debugging

Eight interactive lessons and thirty class activities covering defect analysis, test design, automation, profiling, optimization, memory, ethics and compliance, and a mobile capstone. Run it as a twice-weekly on-ground course, or work the whole thing yourself as a self-paced independent study — every lesson stands alone without an instructor in the room.

1How to use this

Everything here is two kinds of file. The lessons are self-contained HTML — open one in any browser, including straight off a USB stick with no network. Nothing to install, no CDN, no accounts; the simulators, decision trees and knowledge checks run locally. The activities are plain markdown, written to be read in VS Code beside the project you are testing.

Teaching the class

  • One lesson per topic. Topic 1 runs one week; topics 2–8 run two weeks each. Assign the lesson as pre-class reading or project it and work the widgets live — the simulators are built to be driven from the front of the room.
  • Two activities per week, one per meeting. Each of the 30 sessions has exactly one activity, keyed to that day's focus; see the calendar for which lands where.
  • Every activity feeds the graded assignment for its topic. Nothing is busywork — each one produces an artifact the student reuses in the deliverable due at the end of the topic.
  • Activities carry no points. They list deliverables only, posted to Padlet, so you can grade participation however your section does it.

Independent study

  • Work the lessons in order. Each builds on the previous one: taxonomy → reporting → automation → measurement → optimization → memory → ethics → capstone. Budget roughly 110–190 minutes per lesson plus the reading.
  • Do the activities solo or with one partner. Where an activity calls for a team, run it with a partner or take both roles yourself in sequence — the artifact is what matters.
  • Post deliverables to Padlet (or any shared board) so there is a dated record of the work; several assignments ask you to reference it.
  • Use your own project, a provided sample, or any game you can run. No activity requires a specific engine build.
Balanced engine coverage

Every tooling section that differs by engine has both a Unity pane (C#, Unity Test Framework, Unity Profiler, Memory Profiler, Addressables) and an Unreal pane (C++/Blueprint, Automation Spec, Gauntlet, Unreal Insights, LLM). You can run the course in either engine, or both.
